# 03 浮层与反馈系统：弹窗、抽屉与确认交互 (Overlays, Dialog & Drawer)

浮层是 B 端交互中体验灾难的高发区。错用弹窗会导致用户丢失上下文、被强行阻断心流，甚至因误触遮罩导致大段录入数据瞬间丢失。

---

## 一、先分清两组核心概念：模态 ≠ 阻断

| 概念 | 维度 | 本质定义 | 典型案例 |
| --- | --- | --- | --- |
| **模态 (Modal)** | **界面层级** | 是否禁止用户操作遮罩层以下的界面其余部分。 | 微信群聊超员邀请确认：是模态的（底下不可点），但它只针对当前动作，**并不阻断**用户原先的任务。 |
| **阻断 (Blocking)** | **任务流程** | 是否打断用户当前沉浸的操作心流。 | 非模态的页面强制跳转或拦截弹框：即便底下没有黑色遮罩，用户的操作流已经被彻底截断。 |

> **关键心法**：设计前先判断“要解决的是**界面焦点层级**问题，还是**任务打断与确认**问题”，别把“上了模态弹窗”简单等同于“打扰了用户”。在桌面 Web 与 B 端系统上，非模态侧滑面板、气泡框具有极高的操作连贯性。

---

## 二、浮层四选一决策树 (Decision Tree: Modal vs Drawer vs Popconfirm vs Page)

```
                            用户触发的操作
                                   |
              -------------------------------------------
             |                                           |
         轻量动作 / 确认                             信息录入 / 查看
             |                                           |
      高危 / 不可逆？                               内容体量与形态？
       /        \                               /               \
     是          否                         短小/聚焦        深层/长表单/需对比
     |           |                             |                 |
  影响大？    低频简短操作？                 宽幅图片/视频？     保留列表上下文？
   /    \        |                             |                 |
  大     小    气泡确认(Popconfirm)         模态弹窗(Modal)      /       \
  |      |                                                是           否
对话框 气泡框                                           抽屉(Drawer)   独立整页(Page)
(Modal)                                                (400-800px)    (沉浸多步骤)
```

### 选型对比与适用边界

| 组件 | 核心适用场景 | 避免使用的场景 (AvoidWhen) |
| --- | --- | --- |
| **气泡确认框 (Popconfirm)** | 高频、轻量、原地发起的单项操作确认（如删除单行、重试单次任务）。鼠标动线最短。 | 涉及大额资金、批量删除、系统级权限重置等高危操作（阻力不够，容易误触）。 |
| **模态对话框 (Modal / Dialog)** | 短确认、重要公告、任务聚焦型极轻量录入（< 5 个字段）、宽幅图表预览。 | 长表单、深层层级操作、需要频繁参考原页面底表的数据比对任务。 |
| **侧边抽屉 (Drawer)** | 复杂对象详情查看、多字段轻编辑、复杂筛选、且**必须保留列表背景上下文**的场景。 | 包含完整支付流程、多步骤大型向导、或需要把页面独立 URL 分享给他人的场景。 |
| **独立新页面 (Page)** | 字段超过 10 个的大型表单、分步向导（Stepper）、沉浸式创作、需要独立 URL 协同分享的单据。 | 查看一两条属性、几秒钟即可完成的修改（导致用户丢失列表筛选与翻页状态）。 |

## 三、量化尺寸标准 (Sizing Guidelines)

严禁在代码中写随意的 `width: 637px`。严格按照标准化阶梯设计：

### 1. 模态对话框 (Modal) 建议三档宽度
- **小尺寸 (400px)**：轻量二次确认、单项密码验证、短提示。
- **中尺寸 (520px)**（最通用）：标准表单录入（4-6 个字段）、轻量配置弹窗。
- **大尺寸 (720px - 800px)**：复合数据关联、穿梭选择、复杂预览。
- **高度规范**：限定宽度，高度随内容自适应，**严禁超出视口一屏**；若有超长内容，内部区域使用滚动条，且必须固定顶部标题与底部操作栏。**「加载中」与「加载完成」高度必须保持一致，防止界面产生强烈跳动感**。

### 2. 侧边抽屉 (Drawer) 宽度规范
- **窄抽屉 (400px)**：字段详情浏览、轻量属性配置、高级筛选栏。
- **中抽屉 (600px)**：含标签页的标准详情面板、单据流转审计记录。
- **宽抽屉 (800px - 900px)**：复杂业务配置、子表格展示、双列字段轻编辑。

### 3. 移动端/小屏底部弹出层 (Bottom Sheet) 三分屏法则
- **30% 屏高**：单项快速选择、单选操作列表。
- **60% 屏高**：标准信息筛选、中等详情查看。
- **80% 屏高**：长表单录入、复杂树选择（顶部留白 20% 防误触状态栏）。

## 四、高危与不可逆操作：阻力设计与损失心智 (Destructive Actions)

> **核心哲学**：可逆操作去掉阻力（提供撤销 Undo）；不可逆操作必须主动增加摩擦力（给用户适当的心理阻力）。

### 1. 损失心智优先原则
当操作涉及财产扣除、数据彻底粉碎、权限失效等高危后果时：
- **标题必须中立陈述事实与动作**：如“确定解散「技术研发部」群组？”，严禁用含糊口号（如“您确定吗？”或“温馨提示”）。
- **描述区必须清晰交代损失与影响对象**：列明影响人数、关联数据是否丢失、是否不可撤销。
- **动宾文案明确**：主操作按钮严禁用简单的“是/确定”，必须用动宾结构且声明后果，如“彻底删除 (3项)”、“确认扣款 ¥1,200”。

### 2. 危险操作对话框关键技术门禁
1. **防误触背景关闭**：包含录入表单或高危确认的 Dialog，**严禁开启“点击遮罩层关闭 (maskClosable)”**，防止用户辛辛苦苦填完内容手滑点在空白处瞬间丢失！
2. **焦点管理**：弹窗打开后，键盘焦点自动锁定在弹窗内（Esc 触发安全取消关闭）；危险主按钮**严禁默认聚焦**，防止用户敲击回车直接误触发。
3. **加载态锁死**：点击确认后，按钮进入 `loading` 状态，同时禁用取消按钮和右上角关闭按键，防止重复发起多次扣费或破坏请求。

## 五、从列表导航至详情：四大选型判据

适用场景：在表格或卡片列表中点击对象名称，决定如何展示其详情：

| 方式 | 何时使用 | 严禁的反模式 |
| --- | --- | --- |
| **同页内联展开 (Expand Row)** | 详情内容极短（1-3 行补充数据，不超过半屏），查看频率极高。 | 展开后内容有两屏高，把列表后方的数据行挤出视野几十米。 |
| **侧边抽屉 (Drawer)** | 详情超过一屏，且用户需要对照列表其他行快速做判断或轻编辑。 | 详情需要发给同事查看协同，却做成抽屉，根本没有可以分享的独立 URL 路径。 |
| **双栏布局 (左列表/右详情)** | 用户需要连续处理几十条工单或审批任务，需要在条目间极速切换。 | 用户连续处理几十条，却每次都跳进新整页，点击返回后列表滚动位置和筛选条件全部丢失。 |
| **独立详情页 (Page)** | 详情信息量巨大、含多个复杂 Tab 分区、需要对外独立分享单据。 | 查看一两个电话号码也要整页刷新跳转。 |

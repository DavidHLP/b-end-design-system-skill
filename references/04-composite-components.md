# 04 复合组件规范 (Composite Components)

复合组件由多个基础原子组件根据特定业务模式组装而成。它们是 B 端系统从“积木代码”跃升为“工业级业务系统”的核心枢纽。

---

## 一、DataGrid 与 Table 数据表格规范

表格是 B 端系统的灵魂。好表格与坏表格的差距在于**对齐、扫描效率、固定列与响应式细节**。

### 1. 表格列对齐三铁律
- **文本列左对齐**：名称、标题、描述、状态标签等左对齐，符合西方/中文从左往右的阅读流。
- **数值列右对齐**：金额、数量、百分比、时间戳（固定宽字符）右对齐，保证个位、十位、百位垂直完全对齐，让用户能凭视线扫读出数量级差距。
- **操作与定宽标记居中对齐**：复选框勾选列、独立单图标、固定字数的极短状态。

```
[勾选] | 客户名称 (左) | 状态 (左) | 订单金额 (右) | 更新时间 (右) | 操作 (右/中)
[ √ ]  | 阿里巴巴     | [已上线]  |    ¥98,200.00 | 2026-10-24   | 编辑  查看
```

### 2. 冻结固定列 (Sticky Columns) 与窄屏保护
- **固定列必须显式声明固定像素宽度**（如操作列固定 `width: 120px`），并配合微阴影（`shadow`）指示横向滚动的切分层。
- **禁止遮挡核心列**：在较小分辨率视口下，必须先保证主键识别列与操作列可见；次要字段（如“注册来源”、“备注说明”）设置响应式断点自动隐藏，**严禁出现半截被遮挡且无法横滚的残缺单元格**。
- **表格内部独立横滚**：超宽表格必须包裹在自身容器内滚动，**严禁导致整个浏览器主页面产生横向滚动条**。

### 3. 操作列排版
- 操作列按钮一律采用 `ghost` 或 `link` 纯文本变体，保持表格行视觉平整。
- 超过 3 个操作时，展示最高频的 2 个动作，其余动作收敛进 `...` 更多下拉菜单中。

## 二、FilterPanel 筛选组件的三种形态

严禁在所有页面千篇一律地平铺堆砌输入框。根据筛选项的数量与频次选择最合理的形态：

| 筛选项数量 | 推荐形态 | 交互模式 | 适用场景 |
| --- | --- | --- | --- |
| **轻量 (1–3 项)** | **单行内联筛选 (Inline Bar)** | 搜索框 + 1-2个核心下拉框直接放在表格正上方同一行。右侧放“刷新/导出”。 | 高频查询、选项极少、要求极致垂直空间利用。 |
| **中量 (4–8 项)** | **折叠展开式面板 (Expandable Panel)** | 默认露出一行（主搜索 + 2个常用项 + “展开筛选”按钮）；展开后显示第 2 行和“查询/重置”操作按钮。 | 标准 B 端后台列表、CRM 客户列表、财务流水。 |
| **重度 (9 项以上)** | **侧边高级筛选抽屉 (Filter Drawer)** | 主页面仅留搜索框与“高级筛选”漏斗图标；点击后从右侧滑出抽屉，按分组垂直陈列丰富筛选项。 | 复杂数据仓库、电商选品库、高级多维度分析系统。 |

## 三、DescriptionGrid 描述列表与信息亲密度区隔

用于在详情页或卡片中整齐展示对象的静态属性。

### 1. 结构与排布
- 采用 2 列或 3 列自适应栅格（`grid-cols-2 md:grid-cols-3`）。
- Label 与 Value 视觉对比清晰：Label 采用 `text-secondary`（Slate 600），Value 采用 `text-primary font-medium`（Slate 900）。

### 2. 详情内容区隔的四大层级（从亲到疏）

展示一个对象的海量字段时，必须根据信息亲密度采用梯度区隔手段：

```
① 不通栏分割线 (Subtle Divider)：亲密度最高，用于同一业务小模块内的逻辑换行
② 通栏分割线 (Full Divider)：用于同卡片内不同功能小段的切分
③ 独立白底卡片 (Card Section)：用于独立业务维度（如“基本信息”、“结算账户”、“权限配置”）
④ 标签页 (Tabs)：亲密度最低，用于信息体量庞大、互不依赖的平级大型模块
```

## 四、BulkActionBar 批量操作浮动条

当表格开启多选（`rowSelection`）时，**绝不要把批量按钮长久堆在表格上方占用死空间**。

### 1. 交互规则
- **常态隐藏**：未勾选任何数据时，浮动条完全隐藏。
- **勾选唤起**：勾选行数 $\ge 1$ 时，以轻量过渡动效从页面底部中央或表格底部向上滑出（`fixed bottom-6` 或嵌入在表格底部状态栏）。
- **三要素齐备**：
  1. **明确数量告知**：“已选择 8 项数据”；
  2. **批量行动点**：如“批量导出”、“批量分配”，高危动作（“批量删除”）用标红危险按钮并触发 ConfirmDialog；
  3. **一键反选与清空**：必须提供“取消选择”快捷动作。

## 五、ImportFlow 导入导出状态机

数据导入是极易出现断点和迷失的高复杂度流程。必须将状态机完整闭环：

```
   [准备导入: Ready]
         │ (用户选择或拖拽文件)
         ▼
   [本地校验: Validating] ──(格式/大小错误)──► [校验拦截: ValidationError] (可重选)
         │ (通过)
         ▼
   [服务端处理: Processing] ──► 显示上传与解析进度条 (不可随意中断)
         │
    ┌────┴────────────────────────┐
    ▼                             ▼
[导入成功: Success]          [导入失败/部分失败: Error]
- 绿标成功告知               - 失败原因清单
- 新增条数、更新条数统计     - 下载错误行 Excel 报告
- "查看导入数据" 按钮        - "重新上传" 按钮
```

## 六、五态检查法与异常页规范 (Five States & Exception Pages)

任何可变区块在交付前，必须逐一验证以下五种状态均有合理的界面承载：

### 1. 界面五态清单
1. **理想状态 (Ideal)**：数据丰满、正常流转。
2. **空状态 (Empty)**：当前无数据。**严禁只留一个死表头**！必须说明为什么为空，并提供明确的后续行动（如“暂无客户数据，[立即录入首个客户]”；如果是筛选无果，提供“清除筛选条件”按钮）。
3. **加载状态 (Loading)**：异步拉取中。组件自带 `loading` 遮罩或骨架屏（Skeleton）；**加载时长 < 1秒不用骨架屏，> 2秒用带文案提示的指示器**。
4. **错误状态 (Error)**：接口异常或网络崩溃。说明错误发生在何处、提供“重新加载”重试按钮，**严禁将底层的堆栈错误信息直接抛给普通用户**。
5. **部分/权限受限状态 (Partial / 403)**：部分字段被脱敏，或整区需要申请权限；提供“申请查看权限”向导入口，严禁简单用 404 或死白屏掩盖。

### 2. 异常页四要素 (Exception Page Essentials)
整页级异常（404、403、500）：
- **情境配图**：缓解用户挫败情绪。
- **错误代码与简短定性**：一眼辨认是网络断开、权限不足还是地址错误。
- **大白话描述**：说明原因。
- **明确出口**：至少提供两个清晰按钮——“返回上一页”与“回到工作台”。
